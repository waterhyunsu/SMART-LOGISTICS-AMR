## 2026-11-18 — `20261118T061956Z_SIM_lecture_hall_v1`

- **목적:** B 가이드 첫 기능의 완료 조건을 확인한다.
  - 같은 쌍을 명시적 시작 Pose로 두 설정에서 다시 실행한다.
  - 도달 불가 구간이 실패로 남는다.
  - 결과를 설정·지도 버전별로 나눌 수 있다.
- **실행 모드:** SIM (planner-only, Gazebo 미사용)
- **조건:**
  - 측정 코드 `6084b6e`
  - 버전: `navfn_compare@b6b5e3a1039a`, `lecture_hall_real@4995e81c1fb1`, `lecture_hall_v1@81133c5442f3`
  - 환경: Docker `amr-path-planner-bench:jazzy` (ROS 2 Jazzy, Nav2 1.3.14, Python 3.12.3), Windows 11 + WSL2, 8 스레드
  - 반복: 예열 1회 + 30회, 반복마다 플래너 순서 교대
- **이전 실험 대비 바꾼 조건:** 시험 실행보다 반복 횟수를 늘리고 예열 1회를 넣었다. 설정·지도·시나리오는 같다.
- **관찰:**
  - 측정 480회가 모두 기대와 일치했다. 도달 가능 6개 실행은 두 설정 모두 30/30이고, 도달 불가 2개 실행은 두 설정 모두 0/30이다.
  - 성공 경로는 모두 목표에서 끝났다(`path_end_error` 0.0 m).
  - 30회 안에서 경로 길이 표준편차는 모든 실행에서 0.0이었다.
  - R1-C 정방향에서 A*가 17.5687 m, Dijkstra가 9.239 m였다. 역방향은 8.9546 / 9.1211 m였다.
  - 계획 시간 중앙값은 0.33~1.04 ms였다.
  - 실패 응답의 `planning_time`은 0으로 와서 빈 값으로 기록했다. `error_msg`는 비어 있었다.
  - 시험 실행(예열 없음, 1회)과 비교하면 R1-A·R1-B 경로 길이는 같았다. R1-C에서는 최대 0.0026 m 달랐다
    (Dijkstra 정방향: 시험 9.2416 / 본 측정 9.239 m, A* 역방향: 8.9535 / 8.9546 m).
- **문제와 원인:**
  - 실행 중에는 문제가 없었다.
  - 시험 실행과의 R1-C 차이(수 mm)는 원인 **[미분석]**이다. 같은 세션 반복에서는 차이가 없었으므로 Nav2 프로세스를 새로 띄운 것이나 예열 유무와 관련 있을 수 있다. 확인하지는 않았다.
- **다음:**
  - 다른 환경과 경로 길이를 교차 비교할 때는 수 mm 허용 오차를 둔다.
  - 공식 지도가 나오면 새 시나리오로 측정한다.
  - 경로 차단(R1-D) 조건을 추가한다.
