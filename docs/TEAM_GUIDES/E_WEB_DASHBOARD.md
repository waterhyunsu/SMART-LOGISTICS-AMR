# E · 강연주 — FastAPI·SQLite·웹 관제

**목표와 범위.** 기존 [web_control](../../web_control/)에서 작업 등록, 인계 확인 및 상태 화면을 개발한다. Phase 0에는 디렉터리 자리표시자만 있다. A가 내린 상태를 표시하고 실험 데이터는 계산 조건과 함께 저장한다.

1. Job 등록과 인계 요청을 분리한다. 인계할 때 E가 event_id를 발급하고 mission_id·step_id와 함께 발신 내역을 저장한다.
2. A의 응답을 수신해 accepted/rejected/conflict와 응답 미확인을 구분한다. 재시도는 기존 이벤트 ID를 재사용한다. A의 완료 상태와 E의 화면이 어긋나면 A의 결과를 조회해 동기화한다.
3. 운영 화면에서 인계 대기와 도착을 구분하고, B·C·D의 실험 레코드를 환경·설정 버전별로 저장·조회한다.

**완료·테스트.** 임시 SQLite와 A 테스트 대역으로 응답 유실 뒤 재전송, 동일 키·다른 단계 충돌, E 재시작 후 미확인 요청 복구를 검증한다. 같은 인계가 두 번 반영되지 않아야 한다. A와의 복구 통합은 양쪽 프로세스 재시작 후 DB·미션 상태를 대조한다. 전송 방식은 A·E가 별도로 정한다.

**협업.** 최신 main의 `feat/e-web-dashboard`에서 작업하고 PR에 재현 명령과 상태별 결과를 첨부한다. A의 패키지 수정은 협의 후 PR에 사유를 밝히고 공통 타입 변경은 A 승인을 받는다.

**TCREI 프롬프트** · [공통 AI 지침](COMMON_AI_PROMPT.md)과 함께 사용한다.

- Task — web_control/에 Job 요청 및 인계 발신 기록을 만드는 최소 FastAPI·SQLite 흐름을 구현하라.
- Context — E는 요청·기록·표시를 담당한다. A가 최종 상태와 재시도 결과를 제공한다.
- Reference — [계약](../INTERFACES.md) §5.3·11을 읽고 공통 ROS 타입을 유지하라.

- Iterate — 임시 DB에서 검증한 뒤 실제 A 연동 결과를 분리해 PR에 기록하라.
