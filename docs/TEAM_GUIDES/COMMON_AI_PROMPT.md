# 공통 AI 개발 프롬프트

아래 지시와 담당 가이드의 TCREI 프롬프트를 함께 전달한다. 실제 담당 브랜치와 목표 검증 환경을 명시한다.

- **Task** 담당 가이드의 첫 우선순위에서 검증 가능한 기능 한 가지를 구현하라. 해당 역할이 제공할 입력·출력과 완료 조건을 따르라.
- **Context** Ubuntu 24.04, ROS2 Jazzy, Python 3.12 기준이다. 기존 공통 패키지·생성 타입·테스트를 재사용하고 현재 브랜치와 사용자 변경을 먼저 확인하라. MOCK, SIM, REAL을 구분하고 하드웨어는 담당자와 조율한 경우에만 구동하라.
- **Reference** 저장소의 [공통 규칙](../../AGENTS.md), [승인 결정](../DECISIONS.md), [계약](../INTERFACES.md), [실차 검증 절차](../SIM_TO_REAL.md)와 담당 가이드를 읽어라. 최종 기획서와 이후 승인 결정이 기준이다.
- **Evaluate** 기능별 테스트를 작성하고 기존 테스트도 실행해 회귀를 확인하라. 정상·실패·중복 또는 지연 조건을 담당 범위에서 검증하고 재현 명령, 실제 결과와 미검증 항목을 제출하라. 상대 모듈이 준비되지 않으면 테스트 대역의 경계를 명시하라.
- **Iterate** 실패 원인을 수정하고 영향 테스트를 다시 실행하라. 최신 main 기반 기능 브랜치의 PR에 변경 사유, 검증 환경과 결과를 기록하라. 공통 ROS 메시지·서비스 변경은 A 승인 후 반영하라. main 직접 수정·Push·병합은 금지하며 팀장이 PR로 통합한다.
